# demo-recording — Vision & Decision Record

> Status: **agreed** (grill session, initial). Changes to any decision below
> must be recorded here with a date and a one-line rationale.

## The vision in one paragraph

Give the extension a web app URL and some background. It explores the app
like a curious expert, finds the use cases worth showing, and writes a
storyboard that reacts to real screen content. That storyboard is reviewed
and approved in a local side-panel web app. It then records the demo as one
continuous, human-looking take (realistic cursor, realistic typing),
analyses the take, and writes a dense, opinionated, anchored voice-over.
After a second approval it synthesizes the voice (ElevenLabs custom voice
first, with fallbacks), edits the video to the narration (audio-led), and
exports per-scene videos plus one combined end-to-end video. Everything
lives in one working directory.

## Phases (user-facing)

| Phase | Stage (panel tab) | What happens | Human gate |
|---|---|---|---|
| **0. Brief** | Config → Project context | Guided `/demo new` + free-form context + brief-drafting skill (web search only on request) → `brief.md` | brief reviewed (soft) |
| **1. Discover & storyboard** | Storyboard | Agent explores the app (vision-first, DOM-assisted), proposes scenes, order, steps, narration outline and `emphasis` hints; live in the Live panel | **storyboard approval** (hard gate before recording) |
| **2. Record** | Recording | One continuous take of the approved storyboard; `improvise` steps for live inputs; event log + layout snapshots; split into scenes | **recording accepted** (hard gate before the voice-over) |
| **3. Voice over** | Voice over | Keyframes + events + DOM values → anchored VO script → approval → TTS (costs money) → audio-led edit (timeline) | **VO script approval** (hard gate before TTS) |
| **4. Annotations** | Annotations | Designer suggests ~2× zooms/callouts/highlights/…, enables the best half; user toggles, edits, approves | **annotations approval** (hard gate before the final render) |
| **5. Render** | Render | Brand + variants → draft or final render → QA (blocking rules) → `out/` | **final render** needs approvals + QA (or explicit per-item confirmation) |

Each stage is versioned and links to exactly one parent version (D30). Several versions per stage can be accepted, so lines branch; one **working line** is what the panel shows and the agent works on (D44–D47). The project's inputs are kept in a log that both the agent and the panel read (D42).

## Decisions

**2026-10-15 UX grill:** D98–D115 record the selected design direction and its technical choices. The
[UX specification](UX.md) is a **draft for review**, not an implementation
approval or a claim that the new UI has shipped. These decisions refine the
presentation of D39/D48, the browsing and approval semantics of D46, and the
draft workflow of D58; existing safety, lineage and cost gates remain.

| # | Area | Decision | Rationale |
|---|---|---|---|
| D1 | Recording engine | **Playwright + DOM-injected virtual cursor** for the MVP. Bezier/Fitts paths come from `@playwright-labs/ghost-cursor`, typing is human-like. An **OS-capture backend (`--cursor=native`, macOS) comes later** | Deterministic, cross-platform, all tooling in-repo. The native cursor is an optional upgrade, not a dependency |
| D2 | Capture | **CDP screencast** frames with timestamps → ffmpeg. Not Playwright `recordVideo` | `recordVideo` is low-bitrate VP8, so text comes out mushy. The screencast timestamps double as the clock for the event log |
| D3 | Run mode | **Headless recording by default**, `--headed` optional for discovery/debugging | The user keeps working while it records; the panel LIVE view shows progress |
| D4 | Perception | **Vision-first**: screenshots are the source of truth. **DOM harvest** is the precision layer for exact values in the VO | Human-like judgment of what is demo-worthy, with no misread numbers in the narration |
| D5 | Auth | **One-time manual login → storageState** (`0600`, per app). Expired sessions are detected and trigger a re-login prompt. Login never appears in demos | Robust against SSO/MFA, and no passwords are stored |
| D6 | Discovery safety | **Agent judgment**, backed by a hard keyword denylist, a live **mutation audit log** in the panel and an optional per-app `policy.json` override | User preference for speed. The safety net costs nothing in flow |
| D7 | Reactivity | **Deterministic storyboard + `improvise`-flagged steps** (search queries, chat messages, filter choices invented live from what's on screen). The **VO is written from the actual run** | Reproducible recordings. Reactivity lives where the app is nondeterministic, and in the narration |
| D8 | Takes | **One continuous take, split into scenes in the edit.** Scenes with a deep link can be re-shot alone. A failed take **resumes from the last good scene boundary** | Natural flow and continuity. Fragility is contained |
| D9 | Orchestration | **The pi session directs** (skill + tools), a **deterministic Node engine executes** (record, TTS, align, edit, render), **panel actions are injected into the session** as user messages | Reuses pi's agent loop and model choice. Mechanical work stays reproducible and costs no tokens |
| D10 | Side panel | Local web app: **LIVE / REVIEW / VOICE / EXPORT** views. Per-scene approve / request changes / re-run, notes per scene. No drag-and-drop or timeline editor in v1 | Keeps the panel from becoming the product |
| D11 | Sync | **Audio-led, event-anchored.** VO anchors (`[@results-visible]`) plus TTS word timestamps drive cuts, freezes and speed ramps | Narration lands on the exact moment; dead time disappears |
| D12 | TTS | **ElevenLabs (custom voice by name) → OpenAI `gpt-4o-mini-tts` → Kokoro (local)**. A universal whisper alignment covers engines without timestamps. **No engine mixing within one video.** Audio is cached by content hash | Best quality first. Cloud and offline fallbacks. Consistent timing data. **Update (S4):** the ElevenLabs default model is now `eleven_v4`, with `eleven_multilingual_v2` as a fallback when the timestamp endpoint rejects v4 for the account. Keys come from the environment only. |
| D13 | Analysis / QA | **Session model only**, within Anthropic / OpenAI. ElevenLabs is for TTS (and optionally alignment). No Gemini. Temporal QA is **deterministic**: ffmpeg freeze/silence/black detection, an in-page alert/toast/console observer, a check that quoted values exist in the DOM at their anchor time, and whisper drift scoring | Vendor limits. Deterministic checks are more reliable than sparse keyframes |
| D14 | Polish v1 | **Auto-zoom/pan only on events flagged in the storyboard. Captions = step callouts** (not the transcript). **Title card on the full video only.** Background music later | Restraint: zoom everywhere looks cheap, and callouts mark the important steps |
| D15 | Format | **1600×900 CSS viewport @ DPR 2** (3200×1800 capture) → **1920×1080 @ 30 fps H.264**. Configurable | Crisp text and ~1.6x zoom headroom |
| D16 | Workdir | **Configurable root (default `~/DemoRecordings`)**: `apps/<app>/` holds shared auth, policy and discovery cache; `projects/<project>/` holds everything per demo. Versioned and never overwritten | Re-use across demos of the same app, and full history |
| D17 | Brief | **Guided `brief.md` + free-form context**, plus a skill that drafts the brief from whatever is given (interactive, web search on request) and asks for what's missing | The brief drives audience, length and stance |
| D18 | VO persona | **Expert guide in first person.** The **stance** (champion / evaluator / teacher) and motivation are set in the brief. Dense (~150–165 wpm), no filler or marketing superlatives, one takeaway per scene, quotes real on-screen values | "Dense and opinionated" without losing credibility |
| D19 | Language | **English v1.** Language is a brief field, so multilingual later is a matter of config + prompts | `eleven_multilingual_v2` and whisper already support more |
| D20 | Test target | **Bundled fixture SPA** (seeded, static) with dashboard, search, streaming chat, deep links, a slow spinner and an error toast. The full pipeline runs end to end on it with offline TTS | Reproducible vertical-slice tests. Real apps are for acceptance only |
| D21 | QA gating (S5 grill) | **Hard/soft split.** *Blocking*, until fixed or explicitly confirmed: a narrated value not on the page, an error toast or console error in used footage, an anchor off-sync by more than 300 ms. *Warnings:* holds, silences, narrator pauses, filler words | Credibility killers block; cosmetic issues don't |
| D22 | Agent auto-fix | **Mechanical fixes only** (re-time or move anchors, alignment, holds, re-render), stored as **edit overrides** next to the timeline, so the approved script and audio stay untouched and nothing needs re-approval. Changes to content (narration text, values, re-takes, storyboard) are always asked first. Every auto-fix appears in the report | Speed without silently changing approved content |
| D23 | Confidence review | **Measured signals set the level** (high/medium/low with reasons). The model's 1–5 self-rating is shown separately as the "agent's view" and can only **lower** a level. The panel sorts lowest first and says "N items need your eyes". A bulk "approve high-confidence" button needs a click plus a confirmation listing what is skipped | Trust measurement, use the model for soft hints |
| D24 | Brands | **Brand packages:** a **neutral** brand ships in the extension. User brands live in `~/DemoRecordings/brands/<name>/` (nothing trademarked in the repo). They are built by the `demo-brand` skill (`/demo brand new`) from a zip or folder, with a guided prompt explaining what's needed, and previewed and tweaked in the panel's **Brand** tab. Switch with `/demo brand use` or in the panel. Config `brand` sets the default | Reusable branding (e.g. Datadog) without assets in the public repo |
| D25 | Frame and title | **Footage inset (~92 %) on a branded backdrop** with rounded corners and a shadow. The **title card** (app, demo title, date) dissolves (0.8 s) into the first frame under the intro narration. An optional **logo bug** is set per brand (off in neutral) | One coherent produced look |
| D26 | Overlays | **Callouts:** a fixed bottom-left branded pill over the footage, written by the director (`callout:` ≤ 60 chars) and **editable inline in Review**. Edits touch only the overlay and trigger a re-render, never a re-take. **Zoom:** 1.5× (max 1.8×), 0.6 s ease in, hold, 0.5 s out, at most 2 per demo (warning above). **Highlight** (user addition): an opt-in `highlight: true` step flag (the director decides, typically when a callout names an app region). It draws a subtle rounded outline in the brand accent around the step's target box (2 px, ~70 % opacity, faint glow, a few px of padding) that fades with the callout and follows the zoom. No fills, arrows or pulsing *Superseded in part by D31–D37:* annotations are chosen in the Annotations phase, not in the storyboard | Mark steps without covering the story |
| D27 | Subtitles and variants | Transcript **VTT sidecars always**. **Burned-in subtitles** are optional; when enabled, **every video exists in both versions**. The **Export tab** toggles callouts, subtitles and the logo bug. Renders are cached per variant, so a toggle renders only what's missing **Brand switch in Export** (user addition): the brand is part of the variant key. Switching it re-renders from the existing timeline + `raw.mp4` + voice audio, a pure engine job with **no LLM and no TTS**; only missing variants are rendered *Superseded in part by D38/D39:* the Export tab becomes the Render stage | Clean master plus social-ready variants |
| D28 | Out of v1 | Background music stays out. Cursor frame-locking only if unevenness is still noticed | Focus |
| D29 | Voice direction (user addition) | The Voice tab can **nudge the whole narrative**, not just single sections. A direction box (stance, tone, length, focus, free text) → "Draft new version" → the agent writes a complete **new voice-over version** from the same take → the panel shows what changed → **you approve** → "Generate voice & render" runs TTS + edit as engine jobs (only changed sections are synthesized and billed; an estimate is shown first). It can optionally be saved as the project's default direction in the brief | Steer the story cheaply; approvals stay per version |
| D30 | Stage chain (annotation grill) | *Single approval superseded by D44–D46 (branching versions, working line); the stage order and one-parent lineage stay.* **Storyboard → Recording → Voice over → Annotations → Render**, a strict chain: each version links to exactly one parent version (recording → storyboard, voice-over → recording, annotations → voice-over, render → annotations). Version numbers count up per stage and are not hierarchical (annotations v7 can be based on voice-over v4). More flexibility later | One understandable lineage from export back to storyboard |
| D31 | Annotations phase | A new phase **after the voice audio is generated**, so it works on real timings. The Annotation designer uses the recorded scenes, the storyboard's `emphasis` hints and the voice-over script to **suggest about 2× as many annotations as it enables**, ranked by value. The top half is pre-enabled. The user toggles, edits and approves | Decide what to point at once the story and its timing are known |
| D32 | Storyboard hints | The storyboard no longer decides annotations. Steps and scenes can carry free-text **`emphasis:`** (intent only). Legacy `zoom`/`callout` flags still parse and are converted into hints, with a deprecation note | Keep the director's intent without committing early |
| D33 | Upstream change | *Superseded by D44/D45: accepting resets nothing; un-accepting orphans instead.* **Cascade reset:** a new approved upstream version clears downstream approvals and drafts (old versions stay readable on disk). Annotations offer **"import from vN"**, an Annotation-designer task that re-applies the user's manual decisions where they still fit | The chain stays simple; no work is lost |
| D34 | Annotation targets | Any visible element, not only step targets. Recording adds a **layout snapshot** (box, text, role of visible elements) at each step and settle point. Takes recorded before this only have step targets | Narration-driven highlights ("12 of 17 products") need boxes nobody clicked |
| D35 | Annotation types | zoom, callout, highlight, **spotlight**, **redact/blur**, **chapter title**. Spotlight is off unless very strongly suggested (noisy). Redaction and chapter titles are suggested, **off by default and outside the budget**. Hard caps stay: ≤ 2 zooms per demo, no two annotations overlapping in time on the same region | A richer vocabulary, with calm defaults |
| D36 | Budget and filtering | The enabled count follows the **2× ratio** (no fixed per-scene or per-second quota). Each suggestion carries a **noise/value weight**. The Annotations tab shows a **target budget meter** (above or below the suggested optimum) and **filters by type** | Keep long lists manageable and the noise/value balance visible |
| D37 | Annotation review | Each card shows a **still keyframe with the overlay** plus a short, cached, low-res **live clip**. Edits: callout/chapter text, ±0.5 s timing nudges, choosing between zoom target candidates. Every save is a new version. Auto-start after the voice is generated; "Send review to agent" loop as in other stages. A full editor goes to `docs/FUTURE_IDEAS.md` | Judge motion and timing without a full render |
| D38 | Render stage | Final export needs an **approved annotation version**. A watermarked low-res **draft render** works from any version. Render versions are export runs (annotations vN + brand + variants), each with a QA report. QA (D21) blocks only the final export. Subtitles stay a **render option** (VTT always written, burned-in optional), not an annotation | Sign-off stays meaningful; previews stay cheap |
| D39 | Panel as control room | Tabs: **Storyboard · Recording · Voice over · Annotations · Render** (Brand moves into Config, D41; Render keeps a brand dropdown). Each stage tab shows its version picker, "based on …" and approval. **Live becomes a collapsible right-side activity panel** (a bottom drawer on narrow windows): always the log stream, plus a segmented progress bar and a frame preview when there is one. Each stage can configure what it shows. Collapsed, it still shows the stage, the activity or "waiting for you", and the progress bar | One place to watch and steer every stage |
| D40 | Cast (actors) | **Director** (leads, talks to the user, final QA gate), **Researcher** (discovery), **Storyboard writer**, **Operator** (live browser, improvise model), **Voice writer**, **Cutter** (timeline; assembles the per-scene and full videos), **Annotation designer**, **Brand designer**, **QA reviewer** (independent checks, reports only), **Privacy officer** (sensitive data, proposes redactions). Each role is a **skill the Director plays by default**; running a role as a separate model run is opt-in in config (e.g. Operator on a fast model, QA reviewer in a fresh context) | Clear responsibilities without the cost of handing off between separate model runs |
| D41 | Config UI (user addition) | The panel gets a **Config** area with three sections. **Settings:** every option with its effective value, source and docs; edited through a validated form, always diff-confirmed, global or project scope; the raw global and project files shown **read-only** beside it ("open in editor", "reload"); API keys only as set/not set. **Brands:** the Brand tab moves here (Render keeps a brand dropdown per render). **Project context:** brief and its history, the input log, sources and assets, discovery, lineage | One place to see and change how the tool behaves, without hand-editing JSON |
| D42 | Project input log (memory) | Every directional input is recorded in `inputs.jsonl` with stage, version and source (command, panel, chat, agent): brief revisions, `/demo` notes, review notes, voice nudges, annotation reviews, attached sources and assets, and project-relevant chat directions. The agent re-reads it (`demo_rec_project context`) when a project is opened or a session restarts. The Project context view shows the same data | Chat history is lost with the session; the project's memory must survive it and be checkable |
| D43 | Correcting the memory | Inputs are never deleted or edited. The user can mark an entry **outdated / ignore** with a reason; the agent then skips it and the view shows it struck through. The brief stays editable (versioned) | History keeps explaining why versions look the way they do, while regretted directions stop steering |
| D44 | Accept = valid input; versions branch (user change after part 3) | Several versions per stage can be **accepted**, storyboards included. Accepted means "good enough to build on": each accepted version can be the input of the next stage, so lines branch (voice-overs on take-005 *and* take-006). Accepting resets nothing. A version can only be accepted when its parent is accepted and usable. The final render picks one line. *Supersedes the single approval of D30 and the cascade reset of D33* | Compare real alternatives instead of throwing work away |
| D45 | Un-accept flags, never resets | Un-accepting is allowed. Accepted versions built on it stay accepted but become **orphaned** (computed, never stored): they can't be an input, be selected or be rendered as final until the ancestor is accepted again. The confirmation lists what becomes orphaned | Undo stays cheap and explicit |
| D46 | Working line | One selection per project in `state.json`: storyboard vN → take → voice-over → annotations → render. Default per stage: the **most recently accepted** usable child of the line's parent. Selecting a version puts its ancestors on the line and re-picks the stages below. Accepting a version whose parent is on the line makes it the line's selection. Each stage tab has an **input picker** listing every accepted, usable parent version with its lineage. A map view comes later ([FUTURE_IDEAS](FUTURE_IDEAS.md)) | One clear "what am I working on", and every tab follows it |
| D47 | The agent follows the working line | Tools default to it: `demo_rec_record` the line's storyboard, `demo_rec_vo template` its take, `demo_rec_tts` / `demo_rec_edit` its voice-over; explicit versions are allowed if accepted and usable. Panel selection changes reach the agent as a note for its next turn (no turn started) and show in the project context | Panel and agent always mean the same thing |
| D48 | Project screen vs. Config (user addition) | The top bar separates **process steps** (a stepper: Storyboard › Recording › Voice over › Annotations › Render) from everything else. A **Project** tab at the far left is its own step: the **project facts** (title, subtitle, persona, depth `poc`/`showcase`/`sales`, app URL(s) and login state), the project's memory (brief, inputs, sources, lineage) and its **findings** from discovery and recordings. **⚙ Config** at the far right holds all tool configuration — global settings, project-scope overrides and brands — and is never mistaken for a step. *Refines D41: Project context moves from Config to the Project tab* | Clear split between "what this project is and knows" and "how the tool is set up" |
| D49 | Annotation motion (part 7) | Nothing pops in: every type fades (0.15–0.3 s), zooms ease in 0.6 s / out 0.5 s, and three types add a small entrance motion — the **highlight settles** from 1.06×, the **callout rises** 12 px, the **chapter slides in** 16 px from the left (1080p values, scaled). **Redactions never animate** | Produced, calm motion at almost no render cost |
| D50 | Annotation placement (part 7) | Callouts bottom left of the footage; **chapter titles in the lower third** (bottom left), callouts stack above a visible chapter; chapters only in the **full video** (per-scene clips stand alone). Page-space annotations (zoom, highlight, spotlight, redact) **end at the first page change** (route or scroll) after their anchor | Never cover the app's own header; never point at the wrong thing |
| D51 | Redaction strength (part 7) | Blocks of ≥ 16 source px (or ⅓ of the short side) plus a Gaussian blur, never faded, from the anchor to the scene end or the next page change (with a warning to add another) | Irreversible, unlike plain pixelation |
| D52 | Annotation designer (part 8 grill) | A **skill in the main agent** (D40 default): it reads a compact input pack from `demo_rec_annotations action=context` and submits suggestions; the engine resolves, weighs, adds privacy hits, picks the recommended set and writes the version | Visible in chat, your model, no extra model wiring; deterministic parts stay testable |
| D53 | Auto-suggest | Suggestions start **automatically after the sync edit** (config `annotations.autoSuggest`, default on), plus a **Re-suggest** button with extra instructions | v1 is waiting when you open the tab; you can steer it |
| D54 | Privacy suggestions | A **deterministic scan** of layout snapshots (emails, phones, keys/tokens/JWTs, IBAN/card-like numbers, long IDs) **plus the designer's judgement** on names; all disabled redact suggestions with reasons | Reproducible, cheap, and still catches names |
| D55 | Annotation card previews | **Stills eager** (1-frame render at the peak, cached); a click opens a **large preview**, a click on it plays the **clip** (960×540, cached); a low-res scene draft (640×360) with all enabled annotations | Fast to scan, motion on demand |
| D56 | Re-suggest | A new suggestion run **keeps every item the user added, edited or toggled**, regenerates the rest, and says what was kept | Steering never throws away your work |
| D57 | Import from an older version | **Deterministic**: carry what still matches (scene, mark, resolvable target) with its edits; list the rest with a reason. No model call | Predictable carry-over after a new take or VO |
| D58 | Saving annotation edits | Panel edits go to a **draft** (instant stills and budget); **Save as vN** writes one version; the draft survives reloads | No version per click, nothing lost |
| D59 | Final render gate (part 9 grill) | A final needs an **accepted, usable annotation version**; `qa` stays `null` ("not checked", "no QA" in the history) until part 10 adds the QA gate without changing the format | Finals are possible now; QA slots in later |
| D60 | Draft renders | **Full video only, 960×540, fast preset, a small DRAFT corner tag**; from any annotation version, including the panel's unsaved draft | Watch the whole thing quickly without mistaking it for the deliverable |
| D61 | Subtitles | VTT transcripts always; **burn in** is an option that writes `*.subtitled.mp4` **in addition** to the clean files (brand-styled, ≤ 2 lines) | Clean and subtitled versions side by side |
| D62 | Final outputs | full + scenes + `full.vtt`/scene VTTs + `full.callouts.srt` + `poster.jpg` + `render.json` in `render/vN/<variant>/` | Everything a hand-off needs |
| D63 | Who renders | Panel renders are **background engine jobs** (no agent turn, no cost); a **quiet note** tells the agent when one finishes | Rendering is mechanical; the agent stays informed |
| D64 | Retention and delete (user note) | Finals kept; the newest `render.keepDrafts` (3) drafts keep files, older drafts keep only their record; **Delete** in the panel removes files, the record stays as "deleted"; deleting an accepted final asks twice | Disk stays in check; lineage never breaks |
| D65 | The edit renders a draft | `demo_rec_edit` builds the timeline and a **draft render version**; finals only from the Render stage; old `out/edit-vN/` show as legacy renders | One full-quality render per decision, not per change |
| D66 | Annotation selection per render (user note) | **Which annotation types to include is a render option** (default: all enabled; none, chapters only, …); the annotation version stays as approved; switching redactions off needs a confirm; plus **Use no annotations** (an empty version) in the Annotations tab | Approve once, cut several ways |
| D67 | Accepting a render | Finals can be accepted (several): the **deliverable**, shown first, protected from pruning, on the working line; drafts can't be accepted | The stage chain ends in a decision |
| D68 | Brands per render | One render version, **several brands** (× subtitled); each a variant folder; existing variants with the same key are reused | One decision ("the v3 cut"), several looks |
| D69 | When QA runs (part 10 grill) | **Automatically after every final render** (same job); drafts get none; **Re-run QA** in the Render tab | Every deliverable is checked without a step to forget |

| D72 | Drift | Whisper on the rendered audio: **> 300 ms blocks**, 150–300 ms warns | Sync is the product's core promise |

| D80 | Bulk approve | "Approve high-confidence" marks unmarked high items approved after a popup listing approved and skipped items; your marks are kept; accepting the version stays separate. Annotations: badges, "needs eyes" and sorting only | Fast, never blind |
| D81 | Review order | Story order by default with badges; "N need your eyes" chips jump to items; a **riskiest-first** toggle; high items can collapse | The story stays readable |
| D82 | Direction box | Stance, tone and length chips, a focus field and notes, prefilled from the brief and the saved default; "save as default direction" writes the brief's **Voice direction** field; every direction is an input (`kind: nudge`) | Steer the whole narrative in one place |
| D83 | Direction diff | The new version stores its **base**; each section shows an inline word diff vs the base (picker for others); unchanged sections collapse; "changed: N of M" | Review only what moved |
| D84 | Generate voice & render | On an accepted VO on the working line the **panel** runs TTS → edit → draft render as engine jobs (no agent turn) after an estimate popup: sections to synthesize vs cached, characters, ElevenLabs credits (flash/turbo 0.5 per char), and money from `tts.pricePer1kChars` (defaults: list prices, editable). | D85 | Four kinds of hands (part 12) | Every role is labelled **human, model, engine or script**; `docs/ACTORS.md` documents each role's inputs, outputs, tools, what it decides alone, its model profile and its failure modes. ## Explicit non-goals for v1

- Timeline editor, drag-and-drop storyboard editing in the panel.
- Background music.
- Languages other than English (config-ready, not tested).
- Mobile/native apps; non-web targets.
- Gemini or any vendor beyond Anthropic, OpenAI, ElevenLabs.
- Remotion (license requires a paid company license above 3 employees).

## Known limitations (accepted)

- **Canvas/WebGL UIs and cross-origin iframes:** the DOM layer can't see inside them, so only vision works there and quoted values can't be guaranteed. These are flagged in QA.
- **Synthetic cursor:** cursor styles (pointer/text/default) are emulated from the computed `cursor` of the element under the point.
- **CDP screencast throughput at 3200×1800** is a risk. It gets a spike in S1, with 2560×1440 as the fallback.
- **Long continuous takes are fragile.** Resume-from-boundary contains the damage but doesn't eliminate it.
- **Discovery safety is heuristic.** The audit log reports after the fact. Sensitive tenants need `policy.json`.
- **Session expiry mid-take** aborts the take, triggers a re-login prompt, then resumes.
