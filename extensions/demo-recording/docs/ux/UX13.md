# UX13 report: no control under 24 px

Slice UX13 (leftovers grill, UX9c follow-up). WCAG 2.2 success criterion 2.5.8 asks for a 24 x 24 px target. The UX9c
audit counted 48 controls below that across the 56 audited pages (14 screens x 2 themes x 2 widths).

## What it found

The shared components were already right (`ds-btn`, `ds-chip`, `ds-check` and the rest have a 32 px minimum). The
offenders were five leftovers that did not use them:

| Where | What | Fix |
| --- | --- | --- |
| Voice, Render, the review bar, Activity, QA | checkboxes in `label.check` (13 px) | the legacy `check` class is gone; they use `ds-check` (32 px label) |
| the brief's length picker, the Brand editor | range sliders drawn 16 px high | every range input has a 32 px control height (the thumb keeps its look) |
| Voice direction | the Focus text field (21 px) | `ds-input` |
| the brief and the Brand editor | a bare `Reset` button (21 px) | `ds-btn ds-btn--ghost` |
| Render variants table | the mp4 / transcript / poster download links (21 px) | 32 px high, inline-flex |

## Numbers

| | before | after |
| --- | --- | --- |
| small targets, all 56 pages | 48 | **0** |
| serious axe nodes | 0 | 0 |

The audit baseline is now zero everywhere, and `scripts/panel-audit.ts` prints the elements with `AUDIT_WHERE=1`
(`SMALL <screen> <theme> <width> [...]`), so the next offender is named when it appears.

## Evidence

`test/ux13-targets.test.ts`: the baseline has no page with a small target, and Voice, Render, the brief,
Annotations and Config are measured live with the audit's own rule. Layout was checked on screenshots of Voice, the
brief and Render (the taller sliders and the larger links did not move anything else).
